Problem Definition & Solution

Transitioning from manual workflows to digital efficiency

Existing Issues

  • Manual work creates delays and duplicate effort.
  • Employee and policy information is difficult to maintain centrally.
  • Request and bill status lacks real-time visibility.
  • Security is weak without role-based access.

Proposed Solution

  • Secure login-based system for multiple distinct roles.
  • Centralized SQL database for all policy and request data.
  • Automated workflows for approvals, payments, and support.
  • Dynamic date-range reporting and notification logs.

User Roles & Permissions

Access control and domain responsibilities

Admin

Controls companies, policies, employees, and generates reports.

Employee

Searches policies, submits requests, and manages personal claims.

Manager

Reviews requests, approves/rejects with remarks, forwards bills.

Finance

Credits forwarded payments and closes completed policy requests.

Support

Manages public queries, replies via email, stores message history.

Core Business Workflow

Lifecycle of a policy request from creation to closure

1. Search

Employee searches and submits policy request.

2. Record

System creates request and pending bill records.

3. Approve

Manager approves request and adds remarks.

4. Payment

Finance credits payment for forwarded bills.

5. Closure

Request is closed and becomes reportable.

Security & Services

Authentication, session management, and integrations

Security Practices

  • BCrypt Hashing Passwords and reset tokens are securely hashed with salts; raw passwords are never stored.
  • Role-Based Access Protected MVC actions enforce strict session checks before allowing database interactions.
  • Data Protection Remember-me cookies are encrypted via ASP.NET Core data protection before restoring a session.

External Services

  • SMTP via MailKit Dispatches password resets and critical workflow notifications automatically.
  • Template Builder Centralizes branded HTML emails without the need for inline image attachments.
  • Audit Logging EmailNotificationLogs tracks email delivery attempts for compliance.

Claim Limit Tracking

Financial safeguard logic and usage calculations

01

Enforce Rules

Coverage is strictly bounded by Policy.CoverageAmount limit definitions to prevent excess claims.

02

Reserve Temp

Pending claims instantly reserve availability during submission checks to dynamically prevent overdrawing.

03

Deduct Payouts

Approved, paid, and closed claims permanently reduce the remaining active coverage balance for the year.

"Employees submit claims only against active assigned policies and can see coverage, used, pending, and available amounts in real-time."
